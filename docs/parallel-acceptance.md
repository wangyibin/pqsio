# 并行写入验收记录

本轮并行扩展随 v0.0.3 发布；保留 Polars 0.49.1、ABI v1 和数据列定义。

## 性能验收

对比当前实现的同步 Writer 与并行 Writer。每种格式 250,000 条记录，目标分片 25,000 条，4 个生产线程、4 个 Polars/Rayon 线程，绑定 8 个 CPU。预热一次，随后六轮交替顺序测试。
使用小型合成数据和文件系统热缓存，不执行 fsync。以下为中位数；RSS 在回读前采样，包含预先生成的输入。

| 格式 | 编码线程 | 写入耗时（秒） | 相对同步加速 | 峰值 RSS（MiB） |
| --- | ---: | ---: | ---: | ---: |
| pairs | 同步 | 0.130432 | 1.00× | 41.3 |
| pairs | 1 | 0.133522 | 0.98× | 42.8 |
| pairs | 2 | 0.076345 | 1.71× | 46.4 |
| pairs | 4 | 0.052146 | 2.50× | 59.0 |
| pairs | 8 | 0.046947 | 2.78× | 77.5 |
| concat | 同步 | 0.168116 | 1.00× | 44.8 |
| concat | 1 | 0.169920 | 0.99× | 45.7 |
| concat | 2 | 0.099282 | 1.69× | 52.9 |
| concat | 4 | 0.066774 | 2.52× | 62.0 |
| concat | 8 | 0.058620 | 2.87× | 82.7 |

全部 70 次执行（含预热）均通过逐字段回读核对，覆盖 MAPQ 0、1、20 和 q0/q1 计数；concat 另核对 read 计数。
8 线程速度最高但内存开销更大；4 线程的中位数约为同步的 2.50×（pairs）和 2.52×（concat）。1 线程存在调度开销，略慢于同步版。
默认保持 2 个编码线程，调用方可按数据和内存调整。

原始逐轮数据保存在本地忽略目录 `tests/output/parallel-results.json`，复现脚本为 `scripts/run_parallel_bench.py`，数据生成和逐字段检查见 `examples/parallel_bench.rs`。

## 行为验收

- Rust 核心保留同步语义；新增有界队列、预留下一序号位置、固定编码池及按序统计汇总。
- Rust、C ABI、C++17 和 Python 均提供并行 Writer 与 Producer。
- 测试覆盖乱序、重复、缺失序号、批次上限、空输出、完整超大 read、跨批次 read ID、阻塞提交与中止、后台磁盘错误及 staging 清理。
- Python 共享 Producer 多线程提交和 C++ 多线程调用均回读验证；旧同步接口及 CPhasing 兼容性测试保留。
- Producer 可比 Writer 活得更久，Owner 结束后提交明确返回错误。

最终代码检查：

| 检查 | 结果 |
| --- | --- |
| `cargo test --offline --locked --profile dev-release -j 4` | 14 项通过：1 项队列单元测试、13 项存储测试 |
| Python unittest 全套 | 24 项通过，包含原生 C/C++ 与 CPhasing 对并行输出的读取 |
| `cargo clippy --offline --locked --all-targets -- -D warnings` | 通过 |
| `cargo fmt --check`、`git diff --check` | 通过 |
| 最终代码 70 次吞吐测试（含预热） | 全部字段、过滤结果、计数一致 |

所有 Rust 命令均通过项目 Pixi 环境执行。复现步骤及内存/调用契约见 [并行接口文档](parallel.md)。

## 限制

- 这是受控小数据吞吐结果，未验证真实全基因组、冷磁盘、长期运行、Chromap 端到端或 Python 多线程吞吐收益。
- 单批字节上限与有界队列限制原生输入缓冲，不是硬性 RSS 上限；编码工作区、调用方输入及 Python/ctypes 对象另占内存。
- 每批结束分片；小批次可能产生大量小文件。
- 提交成功表示入队；完整校验与 I/O 错误可能在后续提交或 finish 时报告。未成功 finish 的输出不发布。
- 调用方必须让下一序号批次有机会执行；finish 检查已提交序列中的空洞，无法推断从未声明的尾部批次。
- 发布版本为 v0.0.3；v0.0.2 标签保留。
